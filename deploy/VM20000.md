# Dedicated Widows Sons development VM

## Identity and scope
The owner authorised Canada VM20000 with maximum host CPU availability, 16 GiB
RAM and a 500 GiB system disk. It is named `can-widows-sons-dev`, tagged for Widows
Sons and development, and has its own users, databases and application directory.
This is the chapter website and application project, separate from normal Grange
services. The public hostname is `wsmba.the-grange.uk`.

## Migration
Home's source guest is **CT1000**, not a QEMU VM. Its application repository is at
commit `68c6cd357ff6bf5005bc30f73e78a8d0a831a159`, including the PostgreSQL schema
and public API changes that had not reached GitHub main. A source/database package
was copied with SHA-256 verification. The original source guest was returned to its
initial stopped state. A ZFS snapshot and a directly archived filesystem remain on
Home for recovery. The filesystem archive retains original host UID mappings;
it is not an automatically restorable `vzdump` archive.

Only this chapter's PostgreSQL database was restored. It contained one organisation
and no member or event records. The source tree is `/srv/widows-sons/source`; the
original migration package and receipts are in `/srv/widows-sons/migration`.

## Services
- `widows-sons-api.service`: original FastAPI backend, running as `widowsapi`.
- Nginx and a dedicated `widows-sons` PHP-FPM pool, running PHP as `widowsweb`.
- PostgreSQL: chapter application database. The public API role has SELECT access
  only to organisations and event source tables, not member records.
- MariaDB: separate WordPress editorial database and database account.
- `widows-sons-cms-cron.timer`: CMS housekeeping.

WordPress core is downloaded from the official distribution and checked with
WP-CLI checksums. WP-CLI itself is verified against its published SHA-512 checksum.
No third-party builder or plugin bundle is needed: the chapter theme uses normal
blocks and the custom must-use plugin adds content types and editor tools.

`install-cms.py` is a **one-time installation**, after Debian dependencies, source,
the restored PostgreSQL database and Python environment are prepared. It checks the
VM identity marker and refuses an existing credential file. Update source/theme
files deliberately rather than rerunning the installer.

Credentials are stored root-only at `/etc/widows-sons/credentials.json`, outside
Git. Administrator and editor email addresses use reserved `.invalid` placeholders
until real chapter accounts are supplied. Development mail delivery is disabled;
the contact form stores enquiries privately in the CMS.

## Reverse proxy and launch state
The dedicated NPM entry forwards this hostname to the VM's private HTTP listener.
Its metadata and configuration identify Widows Sons and VM20000. Existing proxy
configurations were checksum-checked before and after creating the entry.

Public DNS/Cloudflare is being handled by the owner. No certificate covering the
new hostname existed at setup time; issuance and HTTPS enforcement therefore
remain pending DNS. Do not describe the site as publicly live or ready for editor
sign-in until trusted HTTPS has been checked. Search indexing is disabled for this
development installation.

## Verification
`verify-cms.py` exercises the real running website and CMS REST API: editor page
creation/updates, restricted administration, draft/public rides, contact nonce
validation/private storage, chapter API isolation and migrated row counts. It also
runs the original backend regression suite. The setup passed 27 integration checks
and all five original tests. Temporary published test content is removed from the
public pages after checking. Desktop and 390px phone layouts and mobile navigation
were checked in a rendered snapshot of the deployed site.

Public DNS, publicly trusted TLS, outbound email, and mobile-device builds are not
covered by those checks. The mobile app and its safety functions remain unimplemented.
